# 15 — Terraform Export & Import

Package: `packages/terraform`. Terraform is **generated and parsed only**. InfraSim never runs `terraform init/plan/apply`, never stores cloud credentials, and never downloads providers or modules.

## 1. Goals

- **Export:** canvas design → readable, idiomatic Terraform for AWS, GCP, Azure and OCI.
- **Import:** `terraform show -json` output (plan or state) → canvas, with containment (VPC ▸ subnet ▸ instance), inferred edges ("which request goes where"), and cost/simulation-ready node configs.
- **Teach:** exported code is a learning artifact, with comments explaining each block.

## 2. Export

### 2.1 Output files (downloaded as a ZIP, built client-side with `fflate`)

```
terraform/
├─ providers.tf      # terraform{} + provider blocks (version constraints from config file)
├─ variables.tf      # region, name_prefix, instance sizes, secrets (sensitive, NO defaults)
├─ network.tf        # VPC/VNet/VCN, subnets, routes, gateways, firewalls
├─ compute.tf        # VMs, ASGs, containers, functions, load balancers
├─ data.tf           # databases, caches, queues, storage
├─ ai.tf             # AI service resources where Terraform supports them
├─ outputs.tf        # useful endpoints/ids
└─ README.md         # what this is, how to review, cost warning, unsupported items
```
Multi-cloud designs emit one provider block per provider and prefix filenames if needed.

### 2.2 Generation rules

1. **Use an HCL builder** (typed AST → printer), not string concatenation: correct escaping, deterministic ordering, `terraform fmt`-style output (2-space indent, aligned `=`).
2. **Stable names**: `snake_case(slug(label))`, collision → suffix `_2`. Same design → byte-identical output (snapshot-testable).
3. **References, not IDs**: edges and containment become Terraform references (`aws_subnet.private_a.id`, `aws_security_group.db.id`). Firewall "source = another group" becomes SG-reference rules.
4. **Least privilege defaults**: SG/NSG/firewall rules generated from **edges** (port + protocol from the destination service), source = the caller's group, never `0.0.0.0/0` unless the edge is from the Internet to a public entry.
5. **No secrets**: passwords/keys become `variable "db_password" { type = string, sensitive = true }` with **no default**. Never emit literal secrets. Use provider data sources for images where possible (e.g. AWS AL2023 AMI via SSM parameter data source — verify name) instead of hard-coded IDs.
6. **Header comment** on every file: *"Generated by InfraSim for learning. Review before applying. Applying creates real resources that cost real money."*
7. **TODO markers** for values the simulator cannot know (key pair, domain name, certificate ARN) as variables with descriptions.
8. **Unsupported nodes** (custom services, some AI services) emit a commented stub: `# InfraSim: no Terraform mapping for custom.payment_gateway`.
9. Provider/version constraints come from `packages/terraform/config/providers.json` (verify current versions when implementing; don't hard-code from memory).
10. Capacity mapping: `instances` → `count`/ASG `desired_capacity`; `instanceType` → `instance_type`/`machine_type`/`vm_size`/`shape` + `shape_config`.

### 2.3 Example (AWS, abbreviated)

```hcl
# Generated by InfraSim for learning. Review before applying.
resource "aws_vpc" "main" {
  cidr_block = "10.0.0.0/16"
  tags       = { Name = "main" }
}

resource "aws_security_group" "app" {
  name   = "app"
  vpc_id = aws_vpc.main.id
}

resource "aws_security_group" "db" {
  name   = "db"
  vpc_id = aws_vpc.main.id
}

# Edge: api -> db (TCP 5432)
resource "aws_vpc_security_group_ingress_rule" "db_from_app_5432" {
  security_group_id            = aws_security_group.db.id
  referenced_security_group_id = aws_security_group.app.id
  ip_protocol                  = "tcp"
  from_port                    = 5432
  to_port                      = 5432
}
```

## 3. Import

### 3.1 Accepted input
- `terraform show -json tfplan` (**plan JSON**) — recommended; shows resources with references.
- `terraform show -json` of a **state** — accepted (uses `values.root_module`).
- Raw `.tf` files — **v2 / optional** via an HCL parser (no variable/module evaluation; best effort; clearly labelled).
Input is parsed **in the browser**; nothing is uploaded unless the user saves the design.

### 3.2 Pipeline

```
1. Validate: JSON parse, size ≤ 5 MB, format_version present, supported provider names.
2. Sanitize: drop every `sensitive_values`-flagged value and any key matching
   /password|secret|token|private_key|access_key|client_secret|connection_string/i.
3. Flatten modules: walk `planned_values.root_module` + `child_modules` (or `values.root_module`
   for state); keep `address` (e.g. module.net.aws_subnet.a) for grouping.
4. Classify each resource by type → { node | group | networkObject | edgeSource | ignored }
   using the mapping tables (§2.4, inverted). Unknown types → "unsupported" gray node.
5. Extract configuration into NodeConfig (instance type, engine, storage, multi-AZ, ports, memory, …).
   Resolve vCPU/memory from instance_specs (file 14 §4); unknown → prompt user.
6. Build references from `configuration.root_module.resources[].expressions[*].references`
   (planned ids are often "known after apply").
7. Build containment: subnet → vpc, instance → subnet → (az) ; set parentGroupId.
8. Build NetworkConfig: route tables/routes/associations, gateways, firewalls + rules, peerings, endpoints, DNS.
9. Infer edges (§3.3). Mark `inferred: true` with `confidence` and a `reason`.
10. Auto-layout with ELK (layered, compound nodes) and fit view.
11. Produce Import Report: mapped / unsupported / ignored counts, warnings, inferred edges list.
```

### 3.3 Edge inference ("which request goes where")

| Signal | Inferred edge |
|---|---|
| LB listener → target group → attachment/ASG/ECS service | LB → compute (port from target group) |
| SG-A ingress rule `referenced SG = SG-B` on port P | node(s) using SG-B → node(s) using SG-A on P |
| Lambda/container env var references another resource's endpoint/ARN/URL | caller → that resource |
| Event source mapping / subscription / bucket notification / Pub/Sub push | source → consumer (`async`) |
| API Gateway integration → Lambda/LB | API → target |
| CloudFront/Front Door origin | CDN → origin |
| Route53/Cloud DNS record alias target | DNS → target |
| DB subnet group & app in same subnet group + SG rule | app → DB (only with SG signal) |
| Private endpoint | consumer subnet → service |

Inference is conservative: never invent an edge without at least one concrete signal. The UI shows inferred edges dashed with a badge and lets users confirm/delete.

### 3.4 Defaults after import
- `callType` = `sync` except event/queue signals (`async`).
- `maxInFlightPerInstance` via runtime preset `custom` (user chooses; prompt on first run).
- Latency/capacity from the catalog defaults; user edits afterwards.
- Imported attributes that the simulator ignores are kept in `node.importedAttrs` (display only, read-only panel).

## 4. Safety & privacy

- No credential fields are ever read or stored (sanitizer §3.2). Tests assert that known secret keys never appear in the saved design.
- No network access during import/export.
- Large inputs processed in a worker; hard time limit 10 s.
- Show an "Imports are processed in your browser" notice.

## 5. UI

- **Export** button → modal: choose providers, name prefix, region defaults, include comments; preview files in tabs with syntax highlighting; **Download ZIP** / **Copy**.
- **Import** button → drop zone for `plan.json`; shows Import Report; "Place on canvas"; unsupported resources listed with a link to add as custom nodes.
- Terraform bottom-dock tab shows a **live preview** of generated HCL for the current design (debounced) with diff highlighting on edits.
- Show a hint on how to produce the file: `terraform plan -out=tfplan && terraform show -json tfplan > plan.json`.

## 6. Tests

1. **Snapshot tests** of export for each starter template (byte-identical across runs).
2. HCL validity: parse generated HCL with an HCL parser in CI; optional job runs `terraform validate` when the binary and provider access are available.
3. **Round-trip**: export → synthetic plan JSON (fixtures) → import → graph equals original (nodes, edges, containment) for the supported subset.
4. Import fixtures for each provider (generate with real Terraform where possible; otherwise hand-built and labelled `synthetic`).
5. Secret sanitizer removes all keys matching the deny-list and every `sensitive_values` entry.
6. Edge inference: SG-reference signal yields exactly the expected edge; no signal yields none.
7. Unsupported resource types are retained as gray nodes and counted in the report.
8. Name stability: reordering nodes does not change resource names.
9. Size and time limits enforced.
